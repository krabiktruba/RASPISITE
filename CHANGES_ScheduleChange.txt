################################################################################
# ЧАСТЬ 1. ScheduleChange
################################################################################

Принцип работы
--------------
Постоянное недельное расписание (таблица Day) не меняется. Правка хранится в
таблице "ScheduleChange" и действует ТОЛЬКО на одну дату. Правка находит
занятие по тройке: дата + пара (Pair) + номер пары в этот день
(old_pair_number).

Где кнопки
----------
Страница группы /groups/<id>/schedule/ -> ссылка «Правки на даты» (только для
администратора) включает режим ?edit=1. В этом режиме справа от каждой пары
три квадратные кнопки:
    ⇄  перенос  (открывает форму: новая дата + номер пары)
    ✕  отмена   (выполняется сразу, POST)
    ↻  замена   (открывает форму: другой преподаватель и/или другое название)
Четвёртая кнопка ↩ «вернуть как было» появляется только у пары, у которой уже
есть правка.

После внесения правки в расписаниях (все группы, одна группа, преподаватели)
строка помечается плашкой «Отмена» / «Замена» / «Заменён» / «Перенос» и
пояснением.

# ЧАСТЬ 2. Кузня: изменить / удалить / отменить
################################################################################

Как это работает (без JavaScript)
---------------------------------
В каждой из пяти карточек Кузни (Теги, Типы тегов, Преподаватели, Группы,
Пары) под кнопкой «Добавить» появилась кнопка «Изменить».

1. «Изменить» открывает режим редактирования ЭТОЙ карточки. Режим хранится в
   адресе (/workshop/?edit=group), поэтому одновременно он возможен только на
   одной форме: остальные карточки остаются обычными.
2. Вместо формы показан список существующих записей. Нажатие на название
   открывает форму с настройками этой записи (для группы: название, курс,
   смена, тег, куратор).
3. Под формой кнопки: «Изменить» (сохранить) во всю ширину, ниже в одном
   ряду «Удалить» и «Отменить» (две равные половины).
4. «Удалить» сначала показывает подтверждение с перечнем того, что удалится
   вместе с записью; кнопки подтверждения: «Удалить» и «Отменить» (тоже
   поровну). «Отменить» в подтверждении возвращает к форме записи, «Отменить»
   в форме выходит из режима редактирования.
5. Пока запись не выбрана, показан только список и кнопка «Отменить».

Что нельзя удалить и что удалится вместе с записью
--------------------------------------------------
- Тип тега: нельзя, если у него есть теги.
- Тег: можно; у преподавателей и групп он будет снят.
- Преподаватель: нельзя, если он ведёт пары (сначала заменить его в парах или
  удалить пары). Привязки кураторства и учётных записей снимаются.
- Группа: удаляется вместе со своими парами, занятиями в расписании и
  разовыми правками; студенты остаются, но без группы.
- Пара: удаляется вместе со своими занятиями в расписании и разовыми правками.

Ограничения изменения
---------------------
- У существующей пары нельзя менять группу (поле неактивно): расписание групп
  ссылается на пары своей группы. Нужна другая группа — создать новую пару.
- При смене преподавателя у пары проверяется постоянное расписание: если он
  уже ведёт занятие в то же время у другой группы, изменение отклоняется.
- В режиме редактирования поле названия остаётся в форме выбранной записи
  (иначе у типа тега, у которого одно поле, нечего было бы менять, и
  нельзя было бы исправить опечатку в названии).

Как это выглядит и работает
---------------------------
В «Кузне» в третьем столбце, под «Расписанием звонков», появилась карточка
«Импорт и экспорт».

Экспорт: выбираете набор, нажимаете «Скачать CSV» — браузер скачивает файл.
Рядом кнопка «Пустой шаблон» (файл только с заголовками).

Импорт: выбираете набор, выбираете файл, при желании ставите галочку «Только
проверить, ничего не сохранять», нажимаете «Загрузить». Под формой появляется
отчёт: сколько добавлено / обновлено / без изменений и список ошибок с
номерами строк.

Наборы (в порядке, в котором их удобно загружать):
    Звонки         Вид;Смена;Номер;Начало;Конец
                   (Вид: «Пара» или «Перемена»; ключ: вид + смена + номер)
    Преподаватели  ФИО;Тег
                   (ключ: ФИО)
    Группы         Название;Курс;Смена;Куратор;Тег
                   (ключ: название; куратор — ФИО преподавателя)
    Пары           Группа;Предмет;Преподаватель
                   (ключ: вся строка; существующие пары не меняются)
    Расписание     Группа;День недели;Номер пары;Предмет;Преподаватель
                   (ключ: группа + день + номер пары)
Тег записывается как «Тип: Название»; если такого типа или тега нет, он
создаётся при загрузке. День недели — название (понедельник–суббота) или
число 1-6.

Правила
-------
- Принимаются только файлы в формате экспорта: заголовки должны совпасть
  (порядок столбцов любой, регистр не важен, лишние столбцы — ошибка).
  Произвольный CSV не загрузится.
- Экспорт: UTF-8 с BOM, разделитель «;» (так открывает Excel). Импорт
  понимает ещё разделитель «,» и кодировку Windows-1251; пустые столбцы,
  которые дописывает Excel, игнорируются.
- Всё или ничего: если есть хотя бы одна ошибка, не сохраняется ничего.
  Режим «Только проверить» делает то же самое, но в конце откатывает.
- Ничего не удаляется: строки, которых нет в файле, остаются как были.
  Пустое значение необязательного поля (куратор, тег) в файле снимает его.
- Расписание: пара должна уже существовать (набор «Пары»); один преподаватель
  не может стоять сразу у двух групп в одно время (как в редакторе
  расписания).
- Файл не больше 2 МБ и 5000 строк.
- Студенты и пароли в файлы не входят.

Как применить
-------------
1. Распаковать архивы поверх проекта (миграций нет).
2. Для уже созданной базы выполнить один раз (часть 1):
       python database/add_change_columns.py
   (в create_db.py колонка уже есть — для новой базы это не нужно).
3. Запустить тесты:  python manage.py test --noinput   (157 тестов)
4. Часть 1: страница группы под администратором -> «Правки на даты».
   Часть 2: «Кузня» -> «Изменить» в любой карточке.
   Часть 3: «Кузня» -> карточка «Импорт и экспорт» под расписанием звонков.

Что проверено, а что нет
------------------------
Код проверен статически (компиляция, поиск неопределённых и неиспользуемых
имён, баланс шаблонных тегов, имена URL). Django в среде, где писался код,
установить нельзя, поэтому тесты и страницы ни разу не запускались. Отдельно
запущена проверка разбора CSV (чтение файла, кодировки, разделители,
заголовки, время, дни недели, теги) на заглушках без базы данных — она
прошла. Работа с базой (загрузка, откат, конфликты) проверена только
чтением кода. Результат прогона тестов нужен с вашей стороны.
